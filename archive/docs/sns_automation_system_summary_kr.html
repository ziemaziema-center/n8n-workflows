1. 이 시스템의 목적

이 프로젝트는 Instagram 계정을 빠르게 성장시키고, 조회수·저장·공유·DM 유입을 통해 수익화 기회를 만드는 자동화 시스템이다. 핵심은 “콘텐츠를 자동 생성하고, Telegram에서 사람이 승인한 것만 Instagram에 발행하는 구조”다. 완전 자동 발행이 아니라, 사람이 마지막 품질과 안전을 확인하는 approval 기반 운영 방식을 유지한다.

현재 시스템은 릴스 중심으로 안정화되어 있으며, 캐러셀 발행은 별도 브랜치로 확장 중이다. 콘텐츠 전략은 소비자 관점의 강한 훅, 불편한 질문, 저장 유도, DM 전환을 목표로 한다. 내부적으로는 B2C 중심 콘텐츠를 통해 B2B 해석과 문의를 유도하는 구조다.

3. 콘텐츠 생성 기능

Caption / Hook 생성

  • 한국어 caption 생성
  • 강한 첫 줄 훅, 손해·의심·억울함·궁금증 유도
  • B2C 소비자 관점 우선, B2B 신호는 숨은 구조로 유지
  • 약 100단어 수준의 설명형 caption으로 품질 보강
  • Telegram preview와 Instagram caption 인코딩 깨짐 방지

Media Prompt / 이미지 생성

  • 릴스용 장면 이미지 생성
  • 캐러셀용 이미지 프롬프트 생성
  • OpenAI 이미지 모델은 비용 절감을 위해 gpt-image-1-mini / medium으로 통일
  • b64_json 결과를 PNG 파일로 저장 후 public URL로 변환
  • 이미지 생성 실패 시 fallback 이미지로 Telegram preview 유지

4. Reel 파이프라인

Reel 파이프라인은 현재 가장 안정적인 발행 경로다. generator가 8장 전후의 이미지 장면과 caption을 준비하고, FFmpeg 서비스가 약 10초 내외의 mp4 릴 영상으로 변환한다. 영상은 public URL로 노출되고 Telegram preview에 영상으로 전송된다. 사용자가 Approve Reel을 누르면 approval workflow가 publisher를 호출하고, publisher는 one-shot gate를 통과한 1건만 Instagram에 발행한다.

  • Telegram video preview: 정상
  • Approve Reel 버튼: 정상
  • Instagram Reel publish: 성공 확인됨, 최근 성공 execution 예: 4084
  • caption UTF-8: Telegram 및 Instagram 최종 게시물에서 정상 확인
  • post 성공 후 gate disarm: 적용됨

5. Telegram 승인 UI

Telegram은 운영자가 콘텐츠를 확인하고 발행 여부를 결정하는 제어판이다. 새 preview 메시지는 하나만 보내도록 Collapse to Single Item 처리가 들어가 있으며, 중복 preview 방지를 목표로 한다.

버튼 기능 주의점
Approve Reel 기존 안정 Reel publisher 실행 승인 즉시 발행, 예약 발행 아님
Approve Carousel 별도 carousel publisher 실행 현재 Meta 요청 제한으로 최종 발행은 보류 상태
Approve (Legacy) 기존 메시지 호환용 Reel approve 과거 Telegram 메시지 보호 목적
Regen Text / Regen Media 텍스트 또는 미디어 재생성 흐름 approval/publisher와 분리
Delete 해당 preview 폐기 발행하지 않음

운영 기능과 제어 포인트

승인 기반 발행, 안전장치, 비용 제어, 현재 리스크 정리

6. Carousel 파이프라인

Carousel은 Reel과 별도 경로로 분리되어 있다. generator가 carousel slides와 image prompts를 만들고, 이미지 생성 결과를 public PNG URL로 저장한다. 이후 Approve Carousel 버튼을 누르면 clean_04_carousel_publisher가 이미지별 child container를 만들고, 이를 parent carousel container로 묶은 뒤 최종 publish를 시도한다.

  • carousel preview text: Telegram 메시지 내 [CAROUSEL] 블록으로 표시
  • carousel image URL 생성: 성공, public HTTP 200 확인
  • child container 생성: 성공
  • parent container 생성: 성공
  • 최종 publish: Meta/Instagram 응답 Application request limit reached, code 4, subcode 2207051로 차단

현재 carousel 실패는 단순 문법 문제가 아니라 Instagram 측 행동 제한 또는 요청 제한에 가깝다. 즉시 반복 시도하면 제한이 길어질 수 있어, 자동 재시도는 피하고 일정 시간 후 1회 단위로 검증하는 운영이 안전하다.

7. 안전장치

승인 기반 발행

  • generator는 preview만 생성
  • Instagram publish는 Telegram approve 이후에만 시작
  • Approve Reel과 Approve Carousel은 분리
  • 한 번의 승인으로 한 가지 게시물만 발행

One-shot Gate

  • publisher 실행 전 live publish 허용 여부 확인
  • 승인 요청일 때만 gate arm
  • publish 시도 후 자동 disarm
  • 의도치 않은 자동 발행 방지

Caption Encoding Validator

  • caption에 ??, 반복 물음표, replacement character가 있으면 publish 차단
  • 한국어 깨짐이 Telegram 또는 Instagram에 도달하지 않도록 방어
  • Reel publisher 내부에 유지

Daily Cap / Dedupe

  • 하루 발행 수 제한 기본값 3
  • 성공한 publish만 성공 로그에 기록
  • 동일 action/test_id 중복 approve 방지
  • 발행 폭주 방지 목적

10. 앞으로의 운영 원칙

이 시스템은 “완전 자동으로 많이 올리는 장치”보다 “좋은 preview를 만들고, 사람이 고른 콘텐츠만 안전하게 올리는 성장 운영 장치”에 가깝다. 지금은 Reel을 중심으로 실제 게시 데이터를 쌓고, 저장·공유·DM 반응을 보면서 hook과 주제 메모리를 업데이트하는 단계가 가장 중요하다.

  • Reel은 운영 가능 상태이므로 하루 1~3개 이내로 승인 운영
  • Carousel은 Meta 제한이 풀린 뒤 단일 검증부터 재개
  • 실패 시 자동 재시도 금지, execution ID와 node error 기준으로 진단
  • 성과 데이터는 raw log가 아니라 짧은 memory rule로 압축해 다음 generation에 반영
  • 새 기능 추가보다 안정 발행 3회 연속 성공과 반응 데이터 확보를 우선

한 줄 결론: 현재 시스템은 Reel 중심 Instagram 자동화 운영에는 사용할 수 있는 상태이며, Carousel은 publish 단계에서 플랫폼 제한을 만난 상태다. 핵심 자산은 이미 만들어져 있고, 가장 중요한 안전 구조인 “Telegram 승인 후 1건 발행” 원칙은 유지되고 있다.
