## Baseline Judgment

Baseline score before this improvement run: `81/100`.

Strict independent read-only audit score: `76/100`.

The controller was already much more than a document-only concept: Telegram/n8n/tmux/Codex routing, queue/state schemas, Korean summaries, live smoke records, Docker runner scaffolds, reviewer/retry templates, and telemetry existed.

The main weakness was governance clarity for the user:

- no single multilingual README at the repository root;
- no permanent README language policy;
- no explicit scorecard artifact to decide whether the controller had reached a useful operating threshold;
- no test ensuring that the README policy stays in place;
- remaining live gates were real but not separated from readiness scoring clearly enough.

## Improvement Decision

The council agreed that the next high-leverage patch should not pretend to complete the overnight soak or Docker auth gate. Instead, it should:

1. make the readiness score objective and reproducible;
2. make the README/operator instructions clear in five languages;
3. permanently store the five-language README policy;
4. add validation so this policy and scorecard do not disappear;
5. reduce concrete runtime risks found by the strict audit;
6. record remaining live gates as explicit hardening work, not hidden failures.

## Implemented Runtime Risk Fixes

- Queue writes now use a local `.pending.lock` plus SQLite `BEGIN IMMEDIATE`.
- The tmux runner template now protects dequeue with `flock` or a `mkdir` lock fallback.
- The HTTP kill switch no longer performs broad process-wide `pkill`; it only targets TAC-named tmux sessions.
- Host Codex fallback is no longer enabled by default.
- TAC service startup now defaults Codex sandbox mode to `workspace-write`, not `danger-full-access`.
- README policy and scorecard tests were added so the operator-facing standard is not lost later.

## Post-Improvement Judgment

Post-improvement readiness target: `>= 90/100`.

The scorecard generated by `scripts/tac_scorecard.py` is the source of truth for the current 10-sector score. It measures repository/runtime-readiness evidence, not a false claim that every production live gate is exhausted.
